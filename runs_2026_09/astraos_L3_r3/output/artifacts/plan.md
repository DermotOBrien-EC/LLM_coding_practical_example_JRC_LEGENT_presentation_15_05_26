# Frozen study plan

1. Verify the CSV without modifying it; assert 50,400 positive hourly values, UTC continuity, exact endpoints and train/validation/test counts. `code/common.py` owns loading, split boundaries, metrics and forecast result records. Only the overview may read post-test observations.
2. All six models predict 168 hours from one origin without test observations. Validate using consecutive non-overlapping origins starting 2019-10-01, every 168 hours, including the final 24-hour remainder. Parameters are fit on training data only; previous validation observations may supply context for later validation forecasts, never gradients or coefficient fitting. Score the concatenated 2,208 validation hours with MAPE. Refit every selected configuration from scratch on training plus validation.
3. `code/naive.py` repeats the last observed week. `code/sarima.py` compares two explicit daily SARIMAX orders, with deterministic weekly Fourier regressors derived from timestamps to represent weekly structure honestly. `code/prophet.py` uses Darts Prophet with federal German holidays and daily, weekly and yearly seasonality, comparing two changepoint priors.
4. `code/lightgbm_features.py` compares two tree complexities with prescribed calendar, lag and strictly past rolling features. Recursively substitute predictions for all unobserved lag/rolling values within each week. Fit five quantile models (0.025, 0.1, 0.5, 0.9, 0.975) under the selected configuration for both 80% and 95% intervals; explicitly label recursive intervals as approximate marginal intervals.
5. `code/nbeats.py` preserves the default stack configuration with smaller layer width for a CPU budget. `code/patchtst.py` uses actual PatchTST if present, otherwise Darts TransformerModel, not a mislabeled MLP mixer. Both use 168-hour input/output, quantile likelihood, training-only scaling, up to 30 epochs, and early stopping on the identical rolling-origin validation MAPE. Select epoch count, then refit from scratch for that many epochs. Stride-168 training examples cover the training history without expensive hourly near-duplicates. No tuning uses test scores.
6. `code/forecast.py` orchestrates all six and saves their forecasts and validation records before test scoring. `code/figures.py` produces the required labeled 300-dpi figures. Grouped metric bars use ratios to the baseline with labels showing raw % or MW, avoiding mixed-unit axes. Optional diagnostics depend only on the requested top-two rule. `transcript.md` is a short methods and results report with model limitations, uncertainty diagnostics and reproduction instructions.
7. Verify metric formulas, recursive non-leakage, time splits and quantile ordering with executable tests in `code/test_study.py`. Run the full study, independently recompute metrics from saved predictions, visually inspect figures and inventory every required output. No package installations, external covariates, git operations or writes outside this directory.

Assumptions: UTC calendar days define metrics and timestamp features, with federal holidays only. Jan 2-7 means non-Jan-1 days, not exclusively working days (it includes a weekend). The seasonal-naive baseline may legitimately win; in that event no native interval coverage is fabricated. The task's illustrative annual-lag timestamp is incorrect: 2020-01-01 00:00 UTC minus 8760 hours is 2019-01-01 00:00 UTC. The six classes are fixed before test evaluation; calling the lowest test-MAPE model the winner does not justify production selection on that week alone.
